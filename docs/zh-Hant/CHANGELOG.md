# 更新紀錄

Tatami 的主要變更。本文件是網站與 GitHub Releases 版本說明的權威來源，發布流程會附加安裝及更新說明。Sparkle 的 App 內更新視窗彙整同一次要版本系列的所有修補，因此各節只需記錄自身版本的變更。

<a id="1130-2026-09-03"></a>
## 1.13.0 (2026-09-03)

<a id="new"></a>
### 新增功能
- **跨顯示器還原工作空間集合**：在組合設定中建立有序工作空間鏈，切換任一成員即可還原適合目前顯示器配置的其他成員。所選工作空間保留焦點，已連接的固定成員使用各自顯示器，鏈中的動態成員依優先順序使用下一塊空閒螢幕，其餘空位依現有規則填滿。側邊欄顯示關係，每台受影響的顯示器各自顯示結果回饋。
- **保留常駐浮動控制項**：可用現有 App 選擇器登錄 Notion 等 App。只要登錄的 App 擁有螢幕上高層級的控制項，就不會隱藏該程序，使控制項在切換工作空間後仍可見；一般視窗則排除於焦點、並排、循環切換、拖移及成員操作之外。它們仍可能出現在 Mission Control 中。
- **向外部介面傳送操作回饋**：新增 `hud` 掛鉤發布精簡回饋所用的在地化標題、符號、副標題、完全可見時長、位置、尺寸及已確定顯示器。SketchyBar 等整合可直接鏡像資訊，無須解析記錄；掛鉤失敗回饋不會遞迴發布。

<a id="improvements"></a>
### 改善
- **設定精簡回饋的位置與大小**：可選擇目標顯示器任一邊緣、角落或中央，以及小、預設或大尺寸。進入與離開使用彈簧動畫，設定時長只計算中間完全可見的時間。
- **App 與視窗切換包含共用 App**：借用期間，共用浮動及維持原狀視窗會排在主區域與借用並排區域之後。此設定預設開啟，也可關閉以排除共用 App，縮小切換列表。
- **排查 App 浮動行為**：新指南說明何時需要登錄帶浮動控制項的 App、瀏覽器子母畫面為何會自動排除於並排之外，以及何時仍需登錄才能讓它跨工作空間保持可見。

<a id="fixes"></a>
### 修正
- **將瀏覽器子母畫面排除於配置外**：透過 WindowServer 層級識別 Chrome 與 Dia 的 PiP 視窗，不再將它們列為 BSP 並排視窗；中繼資料查詢失敗時仍保留有效的一般視窗。
- **保留手動調整的分割比例**：邏輯並排成員未變更時，焦點協調與視窗表面替換不再把工作空間重設為 50:50。實際插入及移除仍依設定套用自動平均分配。
- **在游標所在顯示器上切換**：前後工作空間及 App、視窗切換使用游標所在顯示器，而非過時的鍵盤焦點。按住 Option-Tab 時保持起始顯示器，篩除其他顯示器的非並排候選，並避免延後返回的非同步焦點查詢造成跳轉。
- **在正確的顯示器上回報變更**：只有可見鏈實際產生結果時才顯示鏈識別。焦點轉移與借用歸還可共用兩行回饋，各回饋及掛鉤資料都指向發生變更的顯示器。未選取列的工作空間圖示也會保留強調色。

<a id="compatibility"></a>
### 相容性
- **無須修改原設定即可升級**：新增的可見性、切換器、回饋及工作空間鏈欄位都有向下相容的預設值。降級至 Tatami 1.12 前，請備份 `config.toml` 並移除事件為 `hud` 的掛鉤；該版本不識別此事件，且下次成功儲存時不會保留 1.13 專用的鏈與設定欄位。

<a id="1120-2026-08-31"></a>
## 1.12.0 (2026-08-31)

<a id="new-1"></a>
### 新增功能
- **依領域組織的 CLI 自動化**：內建 `tatami` 指令將操作分為設定組合、工作空間、視窗、顯示器、配置和 App 子指令，並提供掛鉤查詢。可依名稱或 UUID 選擇對象，在支援的操作中指定未啟用組合，並要求穩定的 JSON 輸出。CLI 提供觸控板手勢的全部 38 項可執行操作。除組合與工作空間啟用外，對應手勢的指令與快速鍵、手勢共用分派器。啟用指令等處理流程完成後才返回，原有平級指令仍保留為相容別名。
- **透過生命週期掛鉤執行程式**：可在 Tatami 啟動、作用中組合變更，或某工作空間在顯示器上可見時執行程式。在設定中新增與測試，或寫入 `config.toml`；每次執行接收帶版本的 JSON 及便利環境變數，並可明確控制 argv、工作目錄、環境與逾時。失敗顯示於問題列表，不阻擋組合或工作空間切換。

<a id="improvements-1"></a>
### 改善
- **套用前預覽複製內容**：設定組合與工作空間的快捷選單支援重新命名，兩種複製操作都使用與「複製自」相同的可選預覽。可個別選擇工作空間、App、設定與已儲存配置。複製的組合不含切換快速鍵或自動啟用規則；同一組合內複製的工作空間不含會立即衝突的快速鍵識別。
- **維持自動化修改的交易性**：CLI 修改與已檢閱的複製會在儲存前檢查目前設定。複製項目發布前先準備配置副本，無法提交設定時清理副本。
- **隨時查看指令文件**：在設定中開啟內建 CLI 指南，或在 pangmo5.dev/Tatami 閱讀由 `docs/CLI.md` 產生的線上參考。內容包含選擇器、JSON 規約、掛鉤行為、結束狀態及腳本範例。
- **任何寬度都能讀取快速鍵衝突**：記錄控制項在各種尺寸下顯示一致的精簡警告，並透過彈出視窗與 VoiceOver 提供完整的衝突操作。

<a id="fixes-1"></a>
### 修正
- **工作空間快速鍵遵循組合邊界**：不同設定組合可重用同一工作空間鍵或明確指定的快速鍵，不再誤報衝突。全域快速鍵仍與全部組合比對。
- **複製不會默默引入快速鍵衝突**：預覽會指出衝突選項，並在儲存前重新驗證目前設定。真正發生衝突時拒絕整個修改，而非套用部分複製結果。

<a id="1113-2026-08-07"></a>
## 1.11.3 (2026-08-07)

<a id="new-2"></a>
### 新增功能
- **游標跟隨 App 觸發的切換**：啟用滑鼠跟隨焦點後，從 Dock、Spotlight 或 App 切換器啟用 App，會將游標移到實際被置前的視窗，而不只是工作空間。同一工作空間中有該 App 的多個視窗時，也能明確知道哪個取得焦點。

<a id="improvements-3"></a>
### 改善
- **預設跨顯示器記住最近工作空間**：新安裝將「剛才所在的工作空間」視為整個桌面的統一記錄，而非每台顯示器各自記錄。現有設定維持不變。
- **游標跟隨改變焦點視窗形狀的配置指令**：切換分割方向或進入、離開全螢幕縮放時，游標會隨焦點視窗移動，不再留在視窗已離開的並排位置。

<a id="fixes-3"></a>
### 修正
- **動態工作空間重新跟隨滑鼠**：修正動態工作空間顯示過一次後就停在最後一台顯示器的問題。啟用時會移到游標所在顯示器；若本就在該顯示器，則保留正在使用的借用組合。
- **多顯示器解鎖後正確還原**：macOS 會在鎖定畫面背後移除並重新加入顯示器，過去逐次處理所有中間狀態，可能破壞指派、觸發顯示器數量規則切換組合並儲存錯誤結果。現在等待拓樸穩定後再協調，短暫消失又返回的顯示器不改變狀態，真正拔除則只處理一次。
- **游標留在結束拖移的位置**：拖移視窗至新並排位置後，修復某些 App 還原的舊尺寸曾被視為應跟隨的配置變更，造成游標突然跳走。現在由游標觸發的配置不會再移動游標，借用組合內也一樣。
- **呼叫借用後始終聚焦借用區域**：修正無關配置寫入取代借用寫入時，暫存區雖已顯示，焦點與游標卻留在主區域的問題。
- **主工作空間移動時歸還借用**：將借用主工作空間拉至其他顯示器後，借用視窗曾留在原螢幕，直到其他操作觸發重繪。現已修正。
- **可切換到沒有視窗的工作空間**：修正所有視窗都已關閉時，工作空間切換被忽略，App 啟用、隱藏處理與操作回饋皆未執行的問題。
- **補上空出顯示器不再搶焦點**：動態工作空間離開後由其他工作空間補位的背景切換，不再從使用者剛抵達的工作空間拉走鍵盤焦點及游標。
- **檢查更新首次點選即回應**：修正選單列開啟的視窗藏在前景 App 後方，看起來必須點第二次才生效的問題。
- **切換器陰影不再裁切**：面板尺寸包含陰影範圍，各種寬度下都能完整顯示投影。

<a id="1110-2026-07-31"></a>
## 1.11.0 (2026-07-31)

<a id="new-3"></a>
### 新增功能
- **還原各顯示器的上次工作空間**：重新啟動後還原最近符合條件的組合、各顯示器的工作空間歷程與全域使用順序。手動選擇的組合繼續保留；依顯示器條件選擇的組合只在規則仍符合時還原，否則使用最適合目前連接顯示器的組合。

<a id="improvements-4"></a>
### 改善
- **反應更快的視窗追蹤**：視窗身分、能力、位置、焦點、鏡像與標記共用快取優先、合併更新的路徑，不重複同步輔助使用工作。各 App 保持操作順序，但忙碌的 App 不會阻擋其他 App，已被取代的掃描或焦點請求也不能發布舊結果。
- **更清楚準確的視窗切換器**：各 App 圖示會顯示焦點、借用、共用 App、置頂及全螢幕狀態。游標停留會更新實際選取，即使同一 App 有多個視窗，Return 或放開修飾鍵也會確認目前反白的視窗。配置更精簡，並遵循減少動態效果設定。
- **平均分配遵循配置設定**：平均分配指令現在套用設定的自動平均分配軸。關閉自動平均分配時，會重建標準 BSP 樹，而非只在既有不平均的拓樸內均分比例。

<a id="fixes-6"></a>
### 修正
- **可靠處理延遲、隱藏與重現的視窗**：立即回應 WindowServer 可見性變更，移除隱藏表面但保留身分，並在 App 重現後持續校正稍後還原的舊尺寸。慢啟動 App 的首個視窗也會在觀察就緒後立即還原預期焦點、全螢幕位置與尺寸。
- **穩定借用完成與焦點**：冷啟動 App 的首個視窗在借用開始後出現，也會立即並排並聚焦。借用穩定過程中保留精確的主區域焦點及視窗標記，在完整啟用前清除舊標記，並在焦點轉至其他顯示器或返回已可見主區域時保持組合。
- **睡眠與喚醒期間保留配置**：系統睡眠時 WindowServer 拆除顯示結構不會清空即時 BSP 樹。喚醒後重新連接存活的視窗或替換回收後的表面，以完整配置還原，不儲存半還原的暫時狀態。
- **安全還原最近的設定組合**：重新啟動時，只要先前手動選擇的組合仍有效，就不會回到第一個組合；顯示器條件已不符的條件式組合也不會被還原。
- **增減按鈕每次點選都儲存**：間距、時長、標記尺寸、手勢門檻與借用比例都會在 macOS Stepper 每次更新後提交，不再依賴一般點選可能永遠不傳送的編輯結束回呼。
- **設定導覽的全螢幕行為與 App 一致**：虛擬配置編輯器以集合追蹤全螢幕視窗，支援練習工作空間中的多個全螢幕視窗，並在還原已儲存或舊格式草稿時保留狀態。

<a id="190-2026-07-23"></a>
## 1.9.0 (2026-07-23)

<a id="new-5"></a>
### 新增功能

- **修正快速鍵解析與水平調整**：快速鍵字串現在可解析 `-`（減號），水平分割也能正確調整尺寸。

<a id="removed--config-change"></a>

<a id="010-2026-05-27"></a>
## 0.1.0 (2026-05-27)

首個公開版本。這是一款採用 yabai 風格視窗並排的 macOS 工作空間管理工具。將 App 分組至虛擬工作空間，用快速鍵或觸控板滑動切換，並自動並排視窗。無須修改 SIP 或撰寫 shell 指令稿。

<a id="tiling-yabai-style-bsp"></a>
### 並排（yabai 風格 BSP）
- **自動 BSP 並排**：使用 dwindle（螺旋）配置的二元空間分割自動排列視窗。
- **依方向控制視窗**：使用 vim 風格的 `h` `j` `k` `l` 聚焦、交換與調整視窗尺寸。
- **填滿工作空間與分割控制**：可將視窗縮放至填滿工作空間，並切換分割方向。
- **進階配置操作**：支援旋轉、鏡像、平均分配、拖移交換與即時尺寸同步。
- **可設定間距**：可調整內部及外部間距。

<a id="workspaces"></a>
### 工作空間
- **工作空間 App 指派**：依工作空間指派 App，透過快速鍵、滑動或最近工作空間切換。
- **彈性切換工作空間**：支援循環、略過空工作空間和跟隨 App 焦點選項。
- **自動啟動 App**：啟用工作空間時自動開啟已指派的 App。
- **多顯示器配置**：可將工作空間固定至顯示器，或動態跟隨 App。
- **浮動 App 不並排**：浮動 App 不會加入並排配置。

<a id="focus--interface"></a>
### 焦點與介面
- **滑鼠焦點控制**：支援焦點跟隨滑鼠、滑鼠跟隨焦點，以及選用的游標隱藏。
- **選單列顯示目前工作空間**：在選單列顯示作用中工作空間的圖示與名稱。
- **工作空間切換回饋**：切換時顯示螢幕回饋，並使用各工作空間的 SF Symbol 圖示。
- **設定與自動化**：支援 skhd 風格快速鍵語法、純 TOML 設定與腳本 CLI。
