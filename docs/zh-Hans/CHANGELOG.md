# 更新日志

Tatami 的主要变化。本文件是网站和 GitHub Releases 发行说明的权威来源，发布流程会追加安装与更新说明。Sparkle 的应用内更新窗口汇总同一小版本系列的所有补丁，因此各节只需记录自身版本的变化。

<a id="1130-2026-09-03"></a>
## 1.13.0 (2026-09-03)

<a id="new"></a>
### 新增功能
- **跨显示器恢复工作区集合**：在方案设置中创建有序工作区链，切换任一成员即可恢复适合当前显示器布局的其他成员。所选工作区保留焦点，已连接的固定成员占用各自显示器，链中的动态成员按优先顺序使用下一块空闲屏幕，其余空位按现有规则填充。侧边栏显示关系，每台受影响显示器各自显示结果反馈。
- **保留常驻浮动控件**：可用现有应用选择器登记 Notion 等应用。只要登记应用拥有屏幕上高层级的控件，就不会隐藏该进程，使控件在切换工作区后仍可见；普通窗口则排除在焦点、平铺、循环切换、拖动和成员操作之外。它们仍可能出现在 Mission Control 中。
- **向外部界面发送操作反馈**：新增 `hud` 钩子发布紧凑反馈所用的本地化标题、符号、副标题、完全可见时长、位置、尺寸和已确定显示器。SketchyBar 等集成可直接镜像信息，无须解析日志；钩子失败反馈不会递归发布。

<a id="improvements"></a>
### 改进
- **设置紧凑反馈的位置与大小**：可选择目标显示器任意边缘、角落或中央，以及小、默认或大尺寸。进入和退出使用弹簧动画，配置时长只计算中间完全可见的时间。
- **应用与窗口切换包含共享应用**：借用期间，共享浮动及保持原样窗口会排在主区域和借用平铺区域之后。该设置默认开启，也可关闭以排除共享应用，缩小切换列表。
- **排查应用浮动行为**：新指南说明何时需要登记带浮动控件的应用、浏览器画中画为何会自动排除在平铺之外，以及何时仍需登记才能让它跨工作区保持可见。

<a id="fixes"></a>
### 修复
- **将浏览器画中画排除在布局外**：通过 WindowServer 层级识别 Chrome 和 Dia 的 PiP 窗口，不再将它们作为 BSP 平铺窗口；元数据查询失败时仍保留有效的普通窗口。
- **保留手动调整的分割比例**：逻辑平铺成员未变化时，焦点协调和窗口表面替换不再把工作区重置为 50:50。真实插入和移除仍按设置应用自动均衡。
- **在指针所在显示器上切换**：前后工作区及应用、窗口切换使用指针所在显示器，而不是过时的键盘焦点。按住 Option-Tab 时保持起始显示器，过滤其他显示器的非平铺候选，并避免延迟返回的异步焦点查询造成跳转。
- **在正确的显示器上报告变化**：只有可见链实际产生结果时才显示链标识。焦点转移和借用归还可共用两行反馈，各反馈及钩子数据都指向发生变化的显示器。未选中行的工作区图标也会保留强调色。

<a id="compatibility"></a>
### 兼容性
- **无需修改原配置即可升级**：新增的可见性、切换器、反馈和工作区链字段都有向后兼容的默认值。降级到 Tatami 1.12 前，请备份 `config.toml` 并移除事件为 `hud` 的钩子；该版本不识别此事件，且下次成功保存时不会保留 1.13 专用的链和设置字段。

<a id="1120-2026-08-31"></a>
## 1.12.0 (2026-08-31)

<a id="new-1"></a>
### 新增功能
- **按领域组织的 CLI 自动化**：内置 `tatami` 命令将操作分为配置方案、工作区、窗口、显示器、布局和应用子命令，并提供钩子查询。可按名称或 UUID 选择对象，在支持的操作中指定未激活方案，并请求稳定的 JSON 输出。CLI 提供触控板手势的全部 38 项可执行操作。除方案和工作区激活外，对应手势的命令与快捷键、手势共用分发器。激活命令等处理流程完成后才返回，原有平级命令仍作为兼容别名保留。
- **通过生命周期钩子运行程序**：可在 Tatami 启动、活动方案变化或某工作区在显示器上可见时运行程序。在设置中添加和测试，或写入 `config.toml`；每次运行接收带版本的 JSON 和便利环境变量，并可显式控制 argv、工作目录、环境与超时。失败显示在问题列表，不阻塞方案或工作区切换。

<a id="improvements-1"></a>
### 改进
- **应用前预览复制内容**：配置方案和工作区的上下文菜单支持重命名，两种复制操作都使用与“复制自”相同的可选预览。可单独选择工作区、应用、设置和已保存布局。复制的方案不带切换快捷键或自动激活规则；同一方案内复制的工作区不带会立即冲突的快捷键标识。
- **保持自动化修改的事务性**：CLI 修改和已审核复制会在保存前检查当前配置。复制项发布前先准备布局副本，无法提交配置时清理副本。
- **随时查看命令文档**：在设置中打开内置 CLI 指南，或在 pangmo5.dev/Tatami 阅读由 `docs/CLI.md` 生成的在线参考。内容包括选择器、JSON 约定、钩子行为、退出状态及脚本示例。
- **任意宽度都能读取快捷键冲突**：记录控件在各种尺寸下显示一致的紧凑警告，并通过弹出框和 VoiceOver 提供完整的冲突操作。

<a id="fixes-1"></a>
### 修复
- **工作区快捷键遵循方案边界**：不同配置方案可重用同一工作区键或显式快捷键，不再误报冲突。全局快捷键仍与全部方案比较。
- **复制不会静默引入快捷键冲突**：预览会指出冲突选项，并在保存前重新验证当前配置。真正发生冲突时拒绝整个修改，而不应用部分复制结果。

<a id="1113-2026-08-07"></a>
## 1.11.3 (2026-08-07)

<a id="new-2"></a>
### 新增功能
- **指针跟随应用触发的切换**：启用鼠标跟随焦点后，从 Dock、Spotlight 或应用切换器激活应用，会将指针移到实际被置前的窗口，而不只是工作区。同一工作区中有该应用的多个窗口时，也能明确知道哪个获得了焦点。

<a id="improvements-3"></a>
### 改进
- **默认跨显示器记忆最近工作区**：新安装将“刚才所在的工作区”视为整个桌面的统一记录，而非每台显示器各自记录。现有配置保持不变。
- **指针跟随改变焦点窗口形状的布局命令**：切换分割方向或进入、退出全屏缩放时，指针会随焦点窗口移动，不再留在窗口已离开的平铺位置。

<a id="fixes-3"></a>
### 修复
- **动态工作区重新跟随鼠标**：修复动态工作区显示过一次后就停在最后一台显示器的问题。激活时会移到指针所在显示器；若本就在该显示器，则保留正在使用的借用组合。
- **多显示器解锁后正确恢复**：macOS 会在锁屏背后移除并重新加入显示器，过去逐次处理所有中间状态，可能破坏分配、触发显示器数量规则切换方案并保存错误结果。现在等待拓扑稳定后再协调，短暂消失又返回的显示器不改变状态，真正拔出则只处理一次。
- **指针留在结束拖动的位置**：拖动窗口到新平铺位置后，修复某些应用恢复的旧尺寸曾被视为应跟随的布局变化，导致指针突然跳走。现在由指针触发的布局不会再移动指针，借用组合内也一样。
- **调用借用后始终聚焦借用区域**：修复无关布局写入取代借用写入时，暂存区虽已显示，焦点和指针却留在主区域的问题。
- **主工作区移动时归还借用**：将借用主工作区拉到其他显示器后，借用窗口曾留在原屏幕，直到其他操作触发重绘。现已修复。
- **可切换到没有窗口的工作区**：修复所有窗口都已关闭时，工作区切换被吞掉、应用激活与隐藏处理和操作反馈均不执行的问题。
- **填补空出显示器不再抢焦点**：动态工作区离开后由其他工作区补位的后台切换，不再从用户刚到达的工作区拉走键盘焦点及指针。
- **检查更新首次点击即响应**：修复菜单栏打开的窗口藏在前台应用后方，看起来必须点击第二次才生效的问题。
- **切换器阴影不再裁切**：面板尺寸包含阴影范围，各种宽度下都能完整显示投影。

## 1.11.2 (2026-08-04)

<a id="fixes-4"></a>
### 修复
- **锁屏期间保留布局**：锁屏时的临时辅助功能或 WindowServer 快照不再从活动 BSP 布局中移除窗口。锁屏遮罩出现前冻结破坏性的成员变更，等待所有重叠睡眠或会话转换结束，再在解锁后重新连接完整布局。
- **完整的跨显示器工作区反馈**：移动焦点到其他显示器上已可见的工作区时，再次显示反馈而不打乱借用组合。来源显示器同时显示目标工作区与显示器名称，使每次跨屏切换结果清楚。

## 1.11.1 (2026-08-02)

<a id="fixes-5"></a>
### 修复
- **原生标签页变化时保持布局**：创建、关闭或切换标签页时，临时 WindowServer 表面标识不再作为独立窗口进入 BSP 树。即使快速变动，也在实际表面替换时保留原平铺位置、焦点历史、缩放及呈现状态。

<a id="1110-2026-07-31"></a>
## 1.11.0 (2026-07-31)

<a id="new-3"></a>
### 新增功能
- **恢复每台显示器的上次工作区**：重新启动后恢复最近符合条件的方案、各显示器的工作区历史及全局使用顺序。手动选择的方案继续保留；按显示器条件选择的方案只在规则仍匹配时恢复，否则使用最适合当前连接显示器的方案。

<a id="improvements-4"></a>
### 改进
- **响应更快的窗口跟踪**：窗口身份、能力、位置、焦点、镜像和标记共用缓存优先、合并更新的路径，不重复同步辅助功能工作。每个应用保持操作顺序，但繁忙应用不会阻塞其他应用，已被取代的扫描或焦点请求也不能发布旧结果。
- **更清晰准确的窗口切换器**：各应用图标会显示焦点、借用、共享应用、置顶和全屏状态。悬停会更新真实选择，即使同一应用有多个窗口，Return 或松开修饰键也会确认当前高亮窗口。布局更紧凑，并遵循减少动态效果设置。
- **均衡遵循布局设置**：均衡命令现在应用配置的自动均衡轴。关闭自动均衡时，会重建标准 BSP 树，而不只是在已有的不均衡拓扑内均分比例。

<a id="fixes-6"></a>
### 修复
- **可靠处理延迟、隐藏和重现的窗口**：立即响应 WindowServer 可见性变化，移除隐藏表面但保留身份，并在应用重现后继续校正其稍后恢复的旧尺寸。慢启动应用的首个窗口也会在观察就绪后立即恢复预期焦点、全屏位置和尺寸。
- **稳定借用完成与焦点**：冷启动应用的首个窗口在借用开始后出现，也会立即平铺并聚焦。借用稳定过程中保留精确的主区域焦点和窗口标记，在完整激活前清除旧标记，并在焦点转到其他显示器或返回已可见主区域时保持组合。
- **睡眠与唤醒期间保留布局**：系统睡眠时 WindowServer 拆除显示结构不会清空实时 BSP 树。唤醒后重新连接存活窗口或替换回收后的表面，以完整布局恢复，不保存半恢复的临时状态。
- **安全恢复最近的配置方案**：重新启动时，只要之前手动选择的方案仍有效，就不会回到第一个方案；显示器条件已不匹配的条件方案也不会被恢复。
- **步进按钮每次点击都保存**：间距、时长、标记尺寸、手势阈值和借用比例都会在 macOS Stepper 每次更新后提交，不再依赖普通点击可能永远不发送的编辑结束回调。
- **设置向导的全屏行为与应用一致**：虚拟布局编辑器按集合跟踪全屏窗口，支持练习工作区中的多个全屏窗口，并在恢复已保存或旧格式草稿时保留状态。

<a id="190-2026-07-23"></a>
## 1.9.0 (2026-07-23)

<a id="new-5"></a>
### 新增功能
- **交互式设置向导**：首次启动从本机运行应用的元数据和连接显示器生成草稿，依次教授工作区、切换与手势、BSP 平铺、借用与暂存区、浮动与忽略、MFF 与 FFM、应用与窗口切换。练习都在安全的虚拟显示器内进行，早先学到的快捷键在后续课程中仍有效。点击**应用设置**前不会修改真实窗口或 `config.toml`，可随时从**设置 → 通用**重新开始。
- **AI 辅助规划工作区**：描述角色和典型一周，先审核以任务为中心的建议，再修改草稿。Tatami 可为 ChatGPT、Claude、Gemini 等准备带隐私说明的提示词，也可在受支持 Mac 上使用设备端 Apple Intelligence 模型。建议考虑应用元数据、显示器数量及可用区域，有意安排单应用暂存区，绝不查看屏幕内容。
- **可交互的应用与窗口切换器**：按住快捷键时显示紧凑列表，淡入淡出不会中断切换。可用已设快捷键或方向键继续选择，用 Return 或松开修饰键确认，用 Escape 取消，也可直接点击。键盘选择与悬停保持不同的视觉状态；轻按仍立即切换，不闪现列表。

<a id="improvements-6"></a>
### 改进
- **累积式练习界面**：设置向导复用草稿中的工作区、应用分配、布局模式、快捷键和手势。后续练习保留最近使用行为和先前学过的所有命令，最后的焦点与切换课程演练完整设置，而非独立模拟。
- **支持借用区域的焦点与切换**：借用结束前，主区域与借用区域的平铺窗口组成同一个可见切换范围。按应用切换恢复各应用最近的窗口，按窗口切换保留同应用的独立窗口，焦点与鼠标跟随焦点都能跨越两区边界。

本次维护更新在全面增强内部可靠性的基础上，让工作区切换更快、更稳定，并修复多项稳定性问题。

<a id="improvements-17"></a>
### 改进
- **更快的工作区切换**：激活时从缓存读取窗口标识，不再在关键路径上逐个查询辅助功能窗口。切换期间的新请求会取代进行中的请求，因此快速前后切换可越过响应缓慢的工作区，不会停在那里。
- **保留繁忙应用**：应用负载过高、辅助功能查询超时时，会保留最后已知窗口，而不视为“没有窗口”。短暂繁忙的应用不再从平铺、浮动镜像或标记点中消失；单个挂起应用也不会在平铺时冻结主线程数秒。

<a id="fixes-22"></a>
### 修复
- **及时停止浮动镜像采集**：修复多种竞争条件导致 ScreenCaptureKit 流和录屏指示器保留过久的问题。采集现在按严格顺序启动和停止。
- **更可靠地观察 Electron 窗口**：首次观察失败时，部分窗口的尺寸变化和关闭事件会丢失。现在会像其他订阅一样重试，不再留下无效平铺位置。
- **保护损坏的配置**：`config.toml` 的顶层配置方案、共享应用或设置节损坏时，会保留原配置而不是重置，避免下一次写入永久保存重置结果并丢失工作区。无法解析的设置字段也会明确报告，不再静默忽略。
- **可靠处理重启失败**：重启辅助程序无法启动时，Tatami 会继续运行并记录失败，不再把“重新启动”变成直接退出。
