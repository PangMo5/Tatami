# Tatami 현지화와 UX 글쓰기

언어가 달라도 Tatami의 제품 개념은 같아요. 영어를 단어대로 옮기기보다 다음 행동이 쉽게 보이도록 써요. 작업 공간은 작업의 맥락이고, 프로필은 환경에 맞춘 작업 공간 묶음이며, 빌려오기는 다른 작업 공간을 잠시 옆에 두는 기능이에요.

<a id="supported-locales"></a>
## 지원 언어

|로케일|대상|글쓰기 기준|
| --- | --- | --- |
|`en`|전 세계 영어 사용자|Apple처럼 결과와 행동을 분명하게 써요. 익숙한 말을 쓰고, 다음 행동에 도움이 될 때만 구현 방식을 설명해요.|
|`ko`|한국|토스처럼 쉽게 써요. 한 번에 하나의 메시지를 전하고 군더더기를 빼요. 구현보다 좋은 점을 먼저 설명해요.|
|`ja`|일본|LINE과 SmartHR처럼 대화하듯 분명하게 써요. 읽는 수고를 줄이고, 오류에서는 사용자를 탓하지 않고 다음 행동을 안내해요.|
|`zh-Hans`|중국 본토|Ant Design처럼 사용자 중심으로 써요. 중요한 정보와 결과·다음 행동을 먼저 전하고, 명령조나 내부 용어를 피해주세요.|
|`zh-Hant`|대만|대만에서 익숙한 `App`/`顯示器`/`設定`/`快速鍵`를 쓰고, 사용자가 하려는 일을 중심으로 설명해요.|

`zh-Hant`는 현재 대만 용어를 기준으로 해요. 홍콩 표현을 섞지 않아요. 나중에 홍콩을 지원하면 `zh-HK`를 별도로 추가해요.

<a id="tatami-voice"></a>
## Tatami의 말투

- 결과부터 알려줘요. 예: “이 작업 공간을 현재 공간 옆으로 가져와요.”
- 한 문장에는 하나의 생각만 담아요. 필요한 조건은 별도 문장으로 설명해요.
- 내부 구조 대신 사용자가 보고 다루는 대상을 이름으로 써요.
- 버튼은 “구성 적용”, “시스템 설정 열기”처럼 행동을 직접 써요.
- 되돌리기 어려운 결과는 사용자가 확인하기 전에 설명해요.
- 친근한 표현으로 오류를 감추지 않아요. 무엇이 실패했고 다음에 무엇을 할 수 있는지 알려줘요.
- 경로, 명령, 키보드 기호, 앱 이름, 사용자가 정한 작업 공간·프로필 이름은 바꾸지 않아요.

용어를 일관되게 써요. 자연스럽게 하려고 문장 전체를 바꿀 수는 있지만, 기능의 의미를 바꾸면 안 돼요.

한국어에서는 제품명 `Tatami`만 영어로 남겨요. 기능은 작업 공간, 프로필, 공용 앱, 빌려오기, 임시 공간, 항상 위처럼 바로 이해할 수 있게 써요. `플로팅` 같은 기술 음역보다 `항상 위에 두기`처럼 결과를 알려주세요.

<a id="english-voice"></a>
### 영어 말투

- Apple 글쓰기 지침처럼 분명하고 짧고 유용하게 써요. 방법보다 결과와 좋은 점을 먼저 알려줘요.
- 사용자가 보는 대상과 행동인 `Always on Top`, `Window Switching`, `On-Screen Feedback`를 써요. 내부 용어 `Floating`, `Cycle`, `HUD`, `Overlay`는 대신 사용하지 않아요.
- 버튼과 메뉴 명령은 동사로 시작해요. 설정 이름은 켰을 때 어떤 일이 일어나는지 설명해요.
- 빈 화면에는 무엇이 없는지 쓰고 필요하면 다음 행동 하나를 알려줘요. 오류는 실패한 일, 안전하게 남은 내용, 복구 방법을 설명해요.
- 구현을 살펴보거나 설정하는 곳에서만 `BSP`, `TOML`, 파일 이름을 드러내요.

<a id="korean-voice"></a>
### 한국어 말투

- 제목·빈 화면·설명·확인·오류에는 해요체를 써요. 버튼·선택값·섹션 제목은 긴 문장보다 짧은 행동이나 명사로 빠르게 읽히게 해요.
- 상태보다 사용자의 행동을 설명해요. `선택된 항목 없음`은 `선택한 항목이 없어요`로, `추가됨`는 `추가했어요`으로 바꿔요.
- 문제 뒤에는 가능한 다음 행동을 알려줘요. 제목 내용을 본문에서 되풀이하지 않아요.
- 구현 용어보다 익숙한 결과를 써요. `HUD`, `오버레이` 대신 `화면 알림`을 쓰되 `BSP`, `TOML`, 키보드 키 이름처럼 필요한 용어는 유지해요.
- 사용자가 정한 이름 뒤에 달라지는 조사를 붙이지 않아요. `“%@”을 삭제할까요?` 대신 `삭제할까요? · “%@”`처럼 써요.

<a id="japanese-voice"></a>
### 일본어 말투

- 익숙한 구어체를 쓰고 지나친 공손 표현은 덜어내요. 설명은 완전한 `です／ます` 문장으로, 버튼과 메뉴는 짧은 행동으로 써요.
- 딱딱한 번역이나 설명 없는 외래어보다 `借りる`, `常に手前`, `タイル表示`, `一時スペース`, `作業環境`를 써요.
- 빈 화면도 `項目が選択されていません`처럼 완전한 문장으로 써요. 오류에서는 사용자를 탓하지 않고 문제와 다음 행동을 알려줘요.

<a id="simplified-chinese-voice"></a>
### 중국어 간체 말투

- 동작보다 결과를 먼저 알려줘요. 짧고 완전하게 쓰고 실패하면 다음 행동을 분명히 안내해요.
- `应用`, `场景`, `借用`, `置顶`, `窗口切换`, `操作反馈`를 일관되게 써요. 중국 본토 UI에 영어 `App`을 섞지 않아요.
- 짧은 이름에는 불필요한 문장부호를 넣지 않아요. 완전한 문장이나 여러 단계 안내에는 알맞게 사용해요.

<a id="traditional-chinese-voice"></a>
### 중국어 번체 말투

- 대만 용어를 기준으로 해요. `App`, `工作空間`, `設定組合`, `顯示器`, `快速鍵`, `借用`, `置頂`, `視窗切換`, `操作回饋`를 사용해요.
- 기술 용어의 직역보다 작업과 눈에 보이는 결과를 설명해요. macOS에서 익숙한 `點按`, `檔案`, `游標`, `螢幕`를 써요.
- `zh-Hant`에 홍콩 용어를 섞지 않아요. 필요하면 `zh-HK`를 별도 로케일로 추가해요.

<a id="implementation-rules"></a>
## 구현 규칙

- 앱과 `TatamiKit`의 UI 문구는 `Tatami/Resources/Localizable.xcstrings`에 넣어요. `TatamiKit`는 정적 프레임워크라 런타임 카탈로그를 Tatami의 메인 앱 번들이 소유해요.
- 추출한 영어 소스 키는 안정적으로 유지해요. 다듬은 영어 표시 문구는 카탈로그의 명시적 `en` 값에 저장해서 Swift 조회 키를 바꾸지 않고 문구를 개선해요.
- 모델·헬퍼·뷰 사이의 고정 문구는 `LocalizedStringResource`로 전달해요. 사용자 이름과 검색된 앱·화면 이름은 `String`으로 유지해요.
- 문자열 리터럴은 SwiftUI 컨트롤에 직접 넘겨요.
- SwiftUI 초기화 밖에서 실제 `String`이 필요할 때만 `String(localized:)`를 써요.
- 완전한 문장에 값을 넣어요. 번역된 조각을 이어 붙이지 않아요.
- 서식 자리표시자를 보존하고 언어마다 순서를 바꿀 수 있게 해요.
- 숫자와 날짜는 로케일을 반영하는 `FormatStyle`으로 보여줘요.
- 번역 문구를 실행 중에 대문자로 바꾸지 않아요.
- UI 문구에 em dash를 쓰지 않아요. 문장을 나누거나 해당 언어에 맞는 문장부호를 써요.

<a id="documentation-website-and-demo-films"></a>
## 문서·웹·데모 영상

앱 밖에서도 같은 용어와 글쓰기 규칙을 적용해요.

- 영어 문서를 기준으로 두고 `Localization/Docs.json`에서 언어별 README와 안내를 만들어요. 명령, 코드 예제, 식별자, 링크 대상, 명시적인 제목 앵커를 보존해요.
- `Localization/Web.json`에는 완전한 웹 문구를 저장해요. 언어마다 별도 URL과 문서 언어를 두고 탐색, 접근성 이름, 로딩·오류, 문서, 영상 컨트롤까지 번역해요.
- Demo Lab은 별도의 `DemoLab/Localization/Localizable.xcstrings`을 사용해요. 각 데모 앱의 메인 번들에 같은 카탈로그를 넣고, 공용 헬퍼는 `LocalizedStringResource`를 전달해요. 저장할 데모 내용은 해당 촬영 언어로 완전한 문장을 만들어요.
- 영상 자막·제목·입력 문구는 `DemoLab/Localization/Films.json`을 함께 써요. 검증값도 같은 문구에서 만들어요. 번역된 이름은 같을 수 있으니 안정적인 접근성 식별자를 우선 사용해요.
- 각 앱 언어로 녹화하고 검증해요. 영어 UI 위에 번역 자막을 넣은 것만으로는 해당 언어의 앱을 검증했다고 볼 수 없어요.
- 번역이 빠지거나 자리표시자가 달라지면 빌드에서 거부해요. 빌드를 통과시키려고 영어로 조용히 대체하지 않아요.
- 과거 릴리스 노트와 라이선스·저작권 문장은 원문으로 보존해요. 탐색과 설명을 번역하고 공식 원문 링크를 분명하게 제공해요.

<a id="review-checklist"></a>
## 검수 항목

1. `SWIFT_EMIT_LOC_STRINGS=YES`로 빌드한 뒤 컴파일러가 만든 `.stringsdata`를 카탈로그에 동기화해요.
2. 번역할 모든 키에 지원 언어별 값이 있는지 확인해요.
3. 각 번역이 원문의 자리표시자를 그대로 쓰는지 확인해요.
4. 스킴의 Application Language 설정으로 언어마다 한 번씩 실행해요.
5. 설정, 메뉴 막대, 삭제 확인, 빈 화면, 시작 안내 전 단계에서 잘리거나 언어가 섞이지 않는지 살펴봐요.
6. 릴리스 전에는 원어민 검수자가 말투와 용어를 확인해요. 화면 맥락을 보고 문구를 작성하며 기계 번역으로 카탈로그를 채우지 않아요.
