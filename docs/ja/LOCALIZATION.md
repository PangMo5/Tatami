# Tatami のローカライズと UX ライティング

言語が変わっても製品の考え方は同じです。英語を逐語訳せず、次の操作がわかる文章にします。ワークスペースは作業の場、プロファイルは環境に合う作業の組み合わせ、「借りる」は別の作業を一時的に横へ置く機能です。

<a id="supported-locales"></a>
## 対応言語

|ロケール|対象|文章の方針|
| --- | --- | --- |
|`en`|世界の英語ユーザー|Apple のように結果と操作を明確にします。身近な言葉を使い、次の操作に役立つ場合だけ実装を説明します。|
|`ko`|韓国|Toss のようにわかりやすく、一度に一つを伝えます。余分な言葉を省き、実装より先に利点を説明します。|
|`ja`|日本|LINE や SmartHR のように自然で明確な文章にします。読みやすさを大切にし、エラーではユーザーを責めずに次の操作を伝えます。|
|`zh-Hans`|中国本土|Ant Design のようにユーザー中心で書きます。重要な情報、結果、次の操作を先に伝え、命令口調や内部用語を避けます。|
|`zh-Hant`|台湾|台湾で使い慣れた `App`／`顯示器`／`設定`／`快速鍵` を使い、作業を中心に説明します。|

`zh-Hant` は現在、台湾の表現を対象とします。香港の語彙を混ぜず、対応する場合は `zh-HK` を別に追加します。

<a id="tatami-voice"></a>
## Tatami の文章

- 結果を先に伝えます。例：「このワークスペースを、今の作業の横に置きます。」
- 一文に一つの内容を入れ、前提条件は別の文にします。
- 内部の仕組みではなく、ユーザーが扱う対象を名指しします。
- ボタンには「構成を適用」「システム設定を開く」のように操作を書きます。
- 破壊的な結果は、確定する前に説明します。
- 親しみやすい表現でエラーを隠しません。失敗したことと、次にできることを伝えます。
- パス、コマンド、キー記号、アプリ名、ユーザーが付けた作業・プロファイル名は変えません。

<a id="english-voice"></a>
### 英語の文章

- Apple の指針に沿って、明確・簡潔・有用に書きます。手順より結果や利点を先に伝えます。
- ユーザーに見える `Always on Top`、`Window Switching`、`On-Screen Feedback` を使い、内部用語の `Floating`、`Cycle`、`HUD`、`Overlay` に置き換えないでください。
- ボタンとメニューは動詞で始め、設定ラベルは有効にしたときの動作を示します。
- 空の状態では何がないかを示し、必要なら次の操作を一つ伝えます。エラーでは失敗、保持されたもの、復旧方法を説明します。
- 実装を確認・設定する場所でだけ、`BSP`、`TOML`、ファイル名を示します。

<a id="korean-voice"></a>
### 韓国語の文章

- 見出し、空の状態、説明、確認、エラーには韓国語の 해요 体を使います。ボタンや選択肢、区切りの見出しは短い動作・名詞にします。
- システム状態よりユーザーの操作を書きます。`선택된 항목 없음` は `선택한 항목이 없어요` に、`추가됨` は `추가했어요` にします。
- 問題の後には、可能なら次の操作を示します。本文で見出しを繰り返しません。
- 実装用語より身近な結果を伝えます。`HUD`、`오버레이` の代わりに `화면 알림` を使い、必要な `BSP`、`TOML`、キー名は残します。
- ユーザーが付けた名前に変化する韓国語の助詞を付けません。`“%@”을 삭제할까요?` は `삭제할까요? · “%@”` と書き換えます。

<a id="japanese-voice"></a>
### 日本語の文章

- 自然な話し言葉を使い、丁寧な前置きを重ねません。説明は `です／ます` の文、ボタンとメニューは短い操作名にします。
- 硬い翻訳や説明のない外来語より、`借りる`、`常に手前`、`タイル表示`、`一時スペース`、`作業環境` を使います。
- 空の状態も `項目が選択されていません` のような文にします。エラーではユーザーを責めず、問題と次の操作を伝えます。

<a id="simplified-chinese-voice"></a>
### 簡体字中国語の文章

- 操作より結果を先に伝えます。短く完全な文で、失敗したら次の操作を明確にします。
- `应用`、`场景`、`借用`、`置顶`、`窗口切换`、`操作反馈` を一貫して使い、中国本土向けの文に英語の `App` を混ぜません。
- 短いラベルに不要な句読点を付けません。文や複数手順の案内では適切に使います。

<a id="traditional-chinese-voice"></a>
### 繁体字中国語の文章

- 台湾の表現を対象に、`App`、`工作空間`、`設定組合`、`顯示器`、`快速鍵`、`借用`、`置頂`、`視窗切換`、`操作回饋` を使います。
- 技術用語の直訳より、作業と見える結果を説明します。macOS で使い慣れた `點按`、`檔案`、`游標`、`螢幕` を使います。
- `zh-Hant` に香港の語彙を混ぜません。必要なら `zh-HK` を別に追加します。

<a id="implementation-rules"></a>
## 実装のルール

- アプリと `TatamiKit` の UI 文言は `Tatami/Resources/Localizable.xcstrings` に置きます。`TatamiKit` は静的フレームワークなので、実行時カタログは Tatami のメインバンドルが持ちます。
- 抽出した英語キーは固定し、見直した英語の表示文を明示的な `en` に保存します。Swift のキーを変えずに文章を改善できます。
- モデル・ヘルパー・ビュー間の固定文は `LocalizedStringResource` で渡し、ユーザーの名前や検出したアプリ・画面名は `String` のままにします。
- 文字列リテラルは SwiftUI コントロールへ直接渡します。
- SwiftUI の初期化の外で具体的な `String` が必要な場合だけ `String(localized:)` を使います。
- 文全体に値を補間し、翻訳した断片をつなぎません。
- 書式のプレースホルダーを保ち、言語ごとに順序を変えられるようにします。
- 数字と日付はロケールに対応する `FormatStyle` で表示します。
- 翻訳した文を実行時に大文字へ変換しません。
- UI 文言に em dash を使いません。文を分けるか、その言語に合う句読点を使います。

<a id="documentation-website-and-demo-films"></a>
## 文書・Web・デモ動画

アプリの外でも、同じ用語と文章のルールを使います。

- 英語の文書を元にし、`Localization/Docs.json` から各言語の README とガイドを生成します。コマンド、コード例、識別子、リンク先、見出しアンカーは保ちます。
- `Localization/Web.json` に Web の完全な文を保存します。各言語に URL と文書言語を設け、ナビゲーション、アクセシビリティ、読み込み・エラー、文書、動画操作を翻訳します。
- Demo Lab は独立した `DemoLab/Localization/Localizable.xcstrings` を持ち、各デモアプリのメインバンドルに含めます。共有ヘルパーは `LocalizedStringResource` を渡し、保存する内容は撮影言語の完全な文で解決します。
- 字幕、タイトル、入力文は `DemoLab/Localization/Films.json` を共有し、検証値もそこから作ります。翻訳ラベルは同じになることがあるため、安定したアクセシビリティ識別子を優先します。
- 各アプリ言語で録画・検証します。英語 UI に翻訳字幕を重ねただけでは、その言語のアプリを試した証拠になりません。
- 翻訳の欠落やプレースホルダーの変更はビルドで拒否します。通すために英語へ黙って戻しません。
- 過去のリリースノートとライセンス・著作権文は原文を保ちます。案内と説明を翻訳し、正式な原文へ明確にリンクします。

<a id="review-checklist"></a>
## 確認項目

1. `SWIFT_EMIT_LOC_STRINGS=YES` でビルドし、コンパイラが作る `.stringsdata` をカタログに同期します。
2. 翻訳対象の全キーに、各対応言語の値があることを確認します。
3. 各翻訳が元のプレースホルダーを保つことを確認します。
4. スキームの Application Language を指定し、各言語で一度起動します。
5. 設定、メニューバー、破壊的操作の確認、空の状態、ガイド全体で、文字切れや言語の混在を確認します。
6. リリース前に母語話者が表現と用語を確認します。画面の文脈から文章を書き、機械翻訳でカタログを埋めません。
